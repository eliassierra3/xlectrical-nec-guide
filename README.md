# Xlectrical NEC Field Reference

> Interactive, bilingual (EN / ES), offline-first field guide to the **NEC 2023**,
> built for Xlectrical service technicians.

**🔗 Live app:** https://xlectricalnecguide.netlify.app

It's an installable **PWA** — open the link on a phone or tablet and add it to the
home screen. It then opens like a native app and works **offline** in the field.

- **iPhone / iPad (Safari):** Share → *Add to Home Screen*
- **Android (Chrome):** menu ⋮ → *Install app*

---

## Features

- 📖 **Full field guide** — 15 sections and 13 NEC reference tables (grounding &
  bonding, GFCI/AFCI, conductor sizing, wiring methods, water heaters, EV chargers,
  pools & spas, and more).
- 🌐 **One-tap Spanish translation** — the UI is in English; any citation, table, or
  diagram flips to Spanish (and back) with one tap. Content is stored bilingually, so
  it works offline.
- 🏠🏢 **Residential / Commercial filter** — show only what applies to the job.
- 📐 **SVG diagrams** on every section — no external images.
- 🧮 **Conduit-fill calculator** — handles a mix of conductor sizes in one raceway.
- 📴 **Works offline** — installable Progressive Web App.
- ✅ **Verified against the NEC 2023** — accuracy matters; the tables were checked
  against the official code.

## Updating the content (everyday workflow)

All content lives in **`server/src/data/`**. To change the guide:

1. Edit the data — `sections.ts` (guide sections) or `tables.ts` (reference tables).
2. Rebuild the app:
   ```bash
   python3 standalone/build.py
   ```
   That regenerates `web/index.html` (plus the standalone/artifact copies).
3. **Commit & push** (GitHub Desktop → *Push*, or `git push`).
   Netlify **auto-deploys** to the same URL in ~1–2 minutes.

Technicians pick up the update automatically the next time they open the app with
internet — no cache clearing needed.

> Changed the look or a diagram instead? Those live in `standalone/_template.html`
> (CSS, app logic, SVG diagrams, the calculator). Same rebuild step.

## How it's built

There is **one source of truth** — the TypeScript data files — and a small Python
build step. No framework runs in the browser; the shipped app is a single
self-contained HTML file, so it loads instantly and works offline.

```
server/src/data/*.ts  +  standalone/_template.html
                    │
                    ▼   python3 standalone/build.py
                    │
     ┌──────────────┼───────────────────────────┐
     ▼              ▼                             ▼
web/index.html   standalone/index.html      standalone/artifact.html
(the PWA,        (double-click to open       (body-only, for sharing
 served by        locally, offline)           a preview)
 Netlify)
```

## Project structure

```
.
├── server/src/data/        ← CONTENT lives here (single source of truth)
│   ├── sections.ts         #   guide sections (bilingual blocks, steps, diagrams)
│   ├── tables.ts           #   NEC reference tables
│   └── types.ts            #   shared content types
├── standalone/
│   ├── _template.html      #   app shell: CSS, JS, SVG diagrams, calculator
│   ├── build.py            #   build: data + template → the outputs
│   ├── index.html          #   self-contained build (offline, double-click)
│   └── artifact.html       #   body-only build (shareable preview)
├── web/                    ← the PUBLISHED PWA (what Netlify serves)
│   ├── index.html          #   generated by build.py
│   ├── manifest.webmanifest
│   ├── service-worker.js   #   offline cache (network-first app shell)
│   ├── icons/              #   app icons (X mark)
│   └── xlectrical-qr.png   #   QR to the live app (for onboarding techs)
├── netlify.toml            #   deploy config (publish = web/)
├── client/                 #   (incomplete React version — not used in production)
└── server/{db,index,seed}.ts   (Express + SQLite scaffold — not used in production)
```

> The production app is the static PWA in `web/`. The `client/` (React) and the rest
> of `server/` (Express + SQLite) are an earlier full-stack scaffold that was never
> finished — the self-contained build turned out to be the better fit for a read-only
> field reference, so it's what ships.

## Deployment

- **Host:** Netlify, connected to this repo — every push to `main` auto-deploys.
- **Config:** `netlify.toml` publishes the `web/` folder as-is (no build step on
  Netlify). It also sets cache headers so the app shell and service worker refresh
  promptly for already-installed users.
- **Manual alternative:** drag the `web/` folder onto https://app.netlify.com/drop.

## Data accuracy

The reference tables and citations were verified against the **official NEC 2023**.
One notable correction: the conduit-fill values were recomputed from NEC Chapter 9
(Table 4 areas × 53 / 31 / 40 %, ÷ Table 5), because an older source table overstated
them. **Always confirm against the current code and the AHJ before relying on any
value in the field.**
